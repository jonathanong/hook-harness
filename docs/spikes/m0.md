### HMAC and JSON parse cost (partial)

Median added wall-clock time over a no-op that does not read the body, on a local laptop:

| Payload | HMAC        | HMAC + parse |
| ------- | ----------- | ------------ |
| 25 KB   | below noise | below noise  |
| 100 KB  | below noise | below noise  |
| 500 KB  | below noise | below noise  |
| 2 MB    | below noise | about 1 ms   |
| 10 MB   | below noise | about 4 ms   |

These look safe against the Free plan's 10 ms CPU limit, but this is wall-clock time on different hardware. Needs confirming with Cloudflare's CPU metric on a deployed Worker.

### Webhook volume: changes the cost picture

Sampled from `vouchington/vouchington` Actions data:

| Sample                                                        | Workflow runs  |
| ------------------------------------------------------------- | -------------- |
| Weekday, 16:00 UTC hour                                       | 745            |
| Weekday, 04:00 UTC hour                                       | 105            |
| Each of 3 full days checked (API `total_count` caps at 2,500) | at least 2,500 |

PRs opened 2026-10-27 to 2026-11-02: 673.

Only two weekday hours were sampled, so this is a rough range. Assuming an average of 300-450 runs an hour:

- about 7,000-11,000 runs a day
- `workflow_run` delivers `requested`, `in_progress` and `completed`, so about 21,000-33,000 Worker requests a day from that event alone
- `check_suite`, `status`, `push`, reviews, comments and PR events are on top and were not measured

**Likely 30,000-70,000 Worker requests a day from this one repo against a 100,000 Free limit.** Durable Object requests are lower because the Worker drops `requested` and `in_progress`.

Consequences:

- Free may hold, but with little margin on busy days. Past the limit Cloudflare returns errors until 00:00 UTC, so late-day ejections would be lost.
- For Vouchington, plan on **Workers Paid at $5/month** as the realistic cost. Other repos with normal volume can stay at $0.
- A real count needs App delivery logs from a deployed relay.

### Tooling note for M1

`@cloudflare/vitest-pool-workers@0.23.0` has a peer dependency of `vitest ^4.1.0`, and the latest `vitest` is 5.1.0. The Worker package has to stay on Vitest 4 until the pool supports 5. This is a required exception to "always latest".
